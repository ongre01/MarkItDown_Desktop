# UT-006 — Extended Edge Case & Regression Test 확장

## 구현 범위

UT-001~UT-005에서 만든 Qt Test target을 유지하면서 실제 장애 가능성이 있는 filesystem,
Markdown 의미 변환, 비동기 request state 및 process lifecycle 경계를 확장했다. 새 test target이나
test-only production API는 추가하지 않았다.

기존 suite가 이미 검증하던 여러 suffix, 대소문자 확장자, Unicode Markdown, 존재하지 않는
저장 부모 폴더, initial/update 전환 및 out-of-order render 결과, Unicode stdout/stderr와
error-followed-by-finished 중복 실패는 중복 테스트를 만들지 않고 그대로 유지했다.

## 추가 테스트

### DocumentFileOperations

- 빈 source path를 `NotFound`로 분류
- 임시 폴더를 명시적으로 current directory로 설정한 상대 경로 검증과 absolute path 반환
- 공백, 한글 및 mixed-case `.PdF`가 함께 있는 실제 source filename 검증
- 빈 Markdown 저장 시 크기 0인 파일 생성
- 1 MiB Markdown의 전체 byte round trip
- 이미 존재하는 destination을 새 Unicode Markdown으로 교체

모든 파일은 `QTemporaryDir` 안에서 생성한다. 상대 경로 테스트는 `QScopeGuard`로 원래 current
directory를 반드시 복구하며, 테스트 간 mutable filesystem state를 남기지 않는다.

### MarkdownDocumentRenderer

- heading level 1~6을 data-driven test로 검증
- italic과 bold fragment의 character format
- ordered/unordered list의 item 순서와 list style
- link text와 anchor target
- fenced code block의 preformatted element와 code text
- blockquote text와 non-zero quote indentation
- 빈 줄로 분리된 문단 순서, Unicode 및 HTML-sensitive 특수문자 보존
- 2,000개 section으로 구성한 큰 Markdown의 첫/마지막 section과 block 수

전체 HTML 문자열은 비교하지 않는다. 대부분의 검증은 emitted HTML을 `QTextDocument`로 다시
읽어 plain text, block/list/character format을 비교한다. Qt 6.11 Debug에서는 fenced-code
HTML을 두 번째 `QTextDocument`에 다시 읽을 때 Qt 내부 assertion이 발생하므로, code block만
전체 serialization 대신 emitted HTML의 `<pre` 요소와 code text를 선택적으로 검증한다.

### MarkdownRenderState

- 연속된 세 update request 중 최신 ID만 accept
- `invalidate()` 뒤 시작한 새 request만 accept하고 이전 HTML을 제거
- `completeRequest()` 뒤 시작한 새 initial request의 독립된 lifecycle
- 같은 active request에 HTML callback이 반복되면 최신 HTML로 교체

기존 initial → update, completion condition 조합 및 out-of-order callback 테스트와 함께 실행해
stale result 거부 계약을 강화했다. 임의 sleep은 사용하지 않는다.

### MarkItDownManager

- stdout과 stderr가 함께 있는 exit code 0에서 stdout Markdown으로 성공
- 2 MiB stdout의 손실 없는 UTF-8 변환 결과 전달
- process detail 없이 Unicode stderr만 있는 오류 diagnostic
- 한 lifecycle의 연속 process error callback에서 첫 failure만 전달
- 정상 완료 뒤 늦은 duplicate `finished`와 `errorOccurred` callback 무시
- 정상 완료 뒤 같은 Manager에서 두 번째 conversion 성공

Fake runner/resolver만 사용하므로 실제 MarkItDown executable, Python process, network 및
developer별 PATH에 의존하지 않는다.

## 발견한 회귀와 production 수정

정상 `finished(markdown)`을 전달한 뒤 Fake runner가 duplicate `finished`를 보내면 기존
Manager가 stdout을 다시 읽고 `EmptyOutput` failure를 추가로 내보내는 문제를 재현했다.
수정 전 회귀 테스트 결과는 2 passed, 1 failed였고, `failedSpy.count()`의 actual 값은 1,
expected 값은 0이었다.

`MarkItDownManager`에 active conversion guard를 추가했다. process start 직전에 lifecycle을
활성화하고 success 또는 failure terminal signal 전에 비활성화한다. 비활성 상태에서 도착한
stderr-ready, process-error 및 finished callback은 무시하므로 하나의 conversion은 terminal
signal을 최대 한 번만 전달한다. 기존 failure guard와 conversion 시작 시 stderr buffer
초기화 동작은 유지한다.

## 제한사항

- `SourceDocumentError::NotFile`은 Windows의 일반 임시 파일 시스템에서 이식성 있고
  결정적으로 만들 수 없어 기존 UT-001 제한을 유지한다.
- 디스크 고갈이나 `QSaveFile::commit()` 단계의 운영체제 장애는 강제로 만들지 않는다.
- 이번 작업은 Fake 기반 process boundary와 deterministic renderer/file/state test 범위다.
  interactive GUI smoke test와 실제 문서의 MarkItDown 변환은 실행하지 않았다.
