# UT-007 — Test Build / CTest / Verification 통합

## 구현 범위

기존 qmake 테스트를 `unit`, `component`, `ui` 카테고리 집계 프로젝트로 재구성했다.
최상위 `tests/tests.pro`는 세 카테고리를 ordered subdirs로 build/check하며, 각 카테고리는
기존 독립 Qt Test executable을 그대로 유지한다.

```text
tests/tests.pro
  ├── unit/unit.pro             → 4 test executables
  ├── component/component.pro   → 2 test executables
  └── ui/ui.pro                 → 1 test executable
```

카테고리별 또는 전체 suite를 같은 방식으로 실행하고 상세 Qt diagnostic을 보존하도록
`tests/run-tests.ps1`을 추가했다. 실행기는 Qt Test text log를 OS 임시 경로에 기록해
콘솔로 출력하고 정리한다. 선택한 test를 모두 실행한 뒤 실패 target을 모아 0이 아닌 종료 코드를
반환한다.

개발자용 전체 architecture, suite별 목적, build/run 명령, Fake 경계 및 제한사항은
`docs/unit-tests.md`에 통합했다. 실제 명령의 기준인 `agent-rules/BUILD_GUIDE.md`도 같은
workflow로 갱신했다.

## CTest와 coverage 결정

현재 저장소에는 `CMakeLists.txt`가 없고 qmake `MarkItDown_Desktop.pro`가 build source of
truth이다. 따라서 CMake를 새로 도입하거나 CTest만 별도로 추가하지 않았다. qmake의
`CONFIG += testcase`, 카테고리 subdirs 및 `check` target이 현재 테스트 등록 지점이다.

기존 qmake/PowerShell 구성에는 coverage tool이 없으므로 이번 티켓에서 coverage
infrastructure를 추가하지 않았다.

## 검증 결과

## 제외 및 제한

- Interactive GUI smoke test는 실행하지 않았다.
- 실제 입력 파일의 MarkItDown 변환은 실행하지 않았다.
- 실제 process, native dialog 및 network는 기존 설계대로 Fake/controlled dependency로
  대체된다.
- 자세한 filesystem/renderer 제한과 test target 추가 절차는 `docs/unit-tests.md`를 따른다.
