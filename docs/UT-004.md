# UT-004 — DocumentController Component Test

## 구현 범위

`DocumentController`가 변환 backend를 직접 생성하던 경계에
`IMarkItDownManager`를 추가했다. production 기본 생성자는 기존과 동일하게 실제
`MarkItDownManager`를 생성하며, 의존성 주입 생성자는 `std::unique_ptr`로 전달된
구현을 Controller가 소유한다.

```text
DocumentController
        │
        ▼
IMarkItDownManager
   ▲             ▲
   │             │
MarkItDownManager  FakeMarkItDownManager
production         component test
```

`MarkItDownManager`는 같은 인터페이스를 구현하도록 변경했지만 process 실행, executable
탐색, stdout/stderr 처리 및 오류 분류 동작은 변경하지 않았다. Controller도 별도의 변환
상태나 결과 검증을 추가하지 않고 backend의 공개 계약을 그대로 위임·중계한다.

## 검증 시나리오

- 공백과 한글을 포함한 source path가 `convert()`에 정확히 한 번 전달되는지 확인
- Fake의 `running = false`, `running = true`가 `isConverting()`에 그대로 반영되는지 확인
- `started`가 `conversionStarted`로 한 번 전달되는지 확인
- UTF-8 Markdown이 `conversionFinished`에 값 변경 없이 전달되는지 확인
- 모든 `ConversionError` 값과 multiline UTF-8 details가 `conversionFailed`에 값 변경 없이
  전달되는지 데이터 기반으로 확인
- success와 failure 신호가 서로 잘못 중계되지 않는지 확인

현재 Controller에는 중복 상태 검증이나 결과 필터링 책임이 없으므로 별도의 stale/duplicate
negative case는 추가하지 않았다. 해당 lifecycle과 중복 실패 억제는 UT-003의
`MarkItDownManager` component test가 담당한다.

## 격리와 Build integration

`tests/component/tst_DocumentController.pro`를 추가하고 `tests/tests.pro`의 ordered subdirs에
등록했다. 테스트 fixture마다 새 Controller와 Fake를 만들며 mutable state를 공유하지
않는다. 테스트 실행 경로는 Fake Manager만 사용하므로 실제 `QProcess`, MarkItDown CLI,
Python 환경, 파일 시스템, 네트워크 및 임의 sleep에 의존하지 않는다.

새 `IMarkItDownManager.h`는 production application, 기존 Manager component test 및 새
Controller component test의 qmake `HEADERS`에 등록해 각 target에서 moc가 생성되도록
했다.

## 검증 결과

2026-09-14에 Qt 6.11.0 / MSVC 2022 x64 Debug 환경에서 다음을 실제 실행했다.

1. `tests/tests.pro` qmake 성공
2. `nmake /NOLOGO debug`로 기존 다섯 target과 새 Controller target 빌드 성공
3. `nmake /NOLOGO check`로 등록된 여섯 test target 실행 성공
4. `tst_DocumentController.exe` 직접 실행 결과 13 passed, 0 failed, 0 skipped
5. `MarkItDown_Desktop.pro` qmake 및 Debug 애플리케이션 빌드 성공
6. Debug 실행 파일 옆 `python-venv/Scripts/markitdown.exe --help` 종료 코드 0 확인
7. Debug GUI를 실제 실행해 `MarkItDown Viewer` 창, 편집기/미리보기, Open/Convert/Save/
   Save As 버튼과 `Ready` 상태 표시를 확인하고 종료 전 프로세스 `Responding=True` 확인

GUI 자동화에서 `Open` 클릭은 도구 응답 대기 중 timeout되어 파일 대화상자 동작은 검증
완료로 기록하지 않았다. 실제 문서 변환도 실행하지 않았다. 따라서 위 결과는 Fake 기반
Controller 계약, UT-001~003 자동 회귀, production 빌드 및 초기 GUI 표시 smoke 검증
범위다.
