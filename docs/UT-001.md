# UT-001 — Core Unit Test 구현

## 구현 범위

GUI와 외부 MarkItDown 프로세스에 의존하지 않는 다음 production 로직을 Qt Test로
검증한다.

```text
DocumentFileOperations
MarkdownRenderState
ConversionErrorPresentation
MarkdownDocumentRenderer
```

production 동작은 변경하지 않았다. 각 테스트 실행 파일은 실제 production `.cpp`를
직접 빌드해 공개 인터페이스의 관찰 가능한 결과를 검증한다.

## Build system 통합

`tests/tests.pro`를 qmake `subdirs` 집계 프로젝트로 추가했다. 네 테스트는
`tests/unit/` 아래의 독립 실행 파일이며 공통 구성은 `unit_test.pri`에서 C++17,
Qt Test, shadow-build 출력 경로를 설정한다.

```text
tests/
├── tests.pro
└── unit/
    ├── unit_test.pri
    ├── tst_DocumentFileOperations.cpp/.pro
    ├── tst_MarkdownRenderState.cpp/.pro
    ├── tst_ConversionErrorPresentation.cpp/.pro
    └── tst_MarkdownDocumentRenderer.cpp/.pro
```

`CONFIG += testcase`를 사용하므로 집계 프로젝트를 빌드한 뒤
`nmake /NOLOGO check`로 네 실행 파일을 한 번에 실행할 수 있다. 전체 명령은
`agent-rules/BUILD_GUIDE.md`에 반영했다.

## 테스트 시나리오

### DocumentFileOperations

- production에 정의된 11개 지원 확장자와 대문자 `PDF`의 case-insensitive 검증
- 존재하지 않는 파일, 디렉터리, 미지원 `.zip` 파일 오류 분류
- 여러 suffix를 가진 원본 파일의 기본 `.md` 출력 경로
- 확장자가 없는 Save As 경로에 `.md` 추가 및 기존 `.MD` 보존
- English, 한글, 日本語가 포함된 Markdown의 BOM 없는 UTF-8 round trip
- 존재하지 않는 부모 디렉터리로 저장할 때의 결정적 실패 결과와 오류 메시지

모든 파일은 `QTemporaryDir` 또는 `QTemporaryFile` 안에서 만들며 테스트 종료 시
자동 정리된다.

### MarkdownRenderState

- 0이 아닌 Request ID 생성과 최신 ID accept
- 새 요청 시작 시 이전 ID reject
- `invalidate()`와 `completeRequest()` 이후 결과 reject 및 상태 초기화
- initial/update request 구분과 rendered HTML 저장/초기화
- Render 완료와 Editor insertion 완료의 네 가지 조합

stale-result 회귀 시나리오는 request #1 뒤 request #2를 시작하고, #2만 accept되는지
확인한 뒤 #2 완료 후 늦은 #1과 중복 #2가 모두 reject되는지 검증한다. 비동기 sleep은
사용하지 않는다.

### ConversionErrorPresentation

Qt data-driven test로 실제 `ConversionError`의 일곱 값을 모두 검증한다.

```text
AlreadyRunning
ExecutableNotFound
FailedToStart
Crashed
NonZeroExit
EmptyOutput
ProcessFailure
```

각 오류가 비어 있지 않은 production 제목과 사용자 요약의 정확한 mapping을 반환하는지
확인한다.

### MarkdownDocumentRenderer

`QSignalSpy`로 `rendered(requestId, html)` signal의 요청 ID와 결과를 캡처한다. 전체
HTML 직렬화를 exact match하지 않고 `QTextDocument`로 다시 해석해 다음 의미를
검증한다.

- empty Markdown의 빈 plain text
- heading의 텍스트와 heading level
- bold fragment의 글꼴 weight
- 여러 문단의 텍스트 순서
- English, 한글, 日本語 보존

## 검증 결과

2026-09-14에 Qt 6.11.0 / MSVC 2022 x64 Debug 환경에서 다음을 실제 실행했다.

1. `tests/tests.pro` qmake 성공
2. 네 Qt Test target 컴파일 및 링크 성공
3. 네 실행 파일 개별 실행 성공
4. 집계 `nmake /NOLOGO check` 성공
5. `MarkItDown_Desktop.pro` qmake 및 애플리케이션 Debug 빌드 성공
6. 애플리케이션 실행 파일과 같은 폴더의 앱 로컬
   `python-venv\Scripts\markitdown.exe` 생성 확인

## 제한사항

- `SourceDocumentError::NotFile`은 Windows의 일반 임시 파일 시스템 자원만으로
  `exists == true`, `isDir == false`, `isFile == false` 상태를 이식성 있고 결정적으로
  만들 수 없어 이번 테스트에서 직접 생성하지 않았다. 파일 검증의 티켓 필수 분기인
  지원 파일, 누락 파일, 디렉터리, 미지원 확장자는 모두 포함한다.
- `QSaveFile`의 저장 실패는 존재하지 않는 부모 디렉터리로 open 실패를 재현한다. 디스크
  고갈이나 commit 단계의 운영체제 장애는 Unit Test에서 강제로 만들지 않는다.
- renderer의 headless 테스트 로그에는 Qt 6.11의 기본 폰트 pixel size 관련 `QWARN`이
  발생하지만 HTML 의미 검증과 종료 코드는 모두 성공했다.
- 이 티켓은 `DocumentController`, `MarkItDownManager`, `MainWindow` 및 실제
  MarkItDown 실행을 검증하지 않는다.
