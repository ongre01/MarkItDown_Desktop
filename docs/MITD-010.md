# MITD-010 — UI 상태 관리 통합

## 구현 범위

- `MainWindow::updateUiState()`를 문서 상태에 따른 UI 갱신의 단일 진입점으로
  사용한다.
- 생성 직후와 문서 열기 및 자동 변환 시작, 렌더링 시작·완료, 변환 실패, Markdown 편집,
  저장 완료 뒤에 `updateUiState()`를 호출한다.
- `Open`, `Convert`, `Save`의 활성화 여부는 `DocumentStatus`별 `switch` 한 곳에서
  결정한다.
- 기존 `Save As`는 `Save`와 같은 활성화 정책을 유지한다.
- 창 제목과 상태 표시줄도 같은 호출에서 현재 문서 상태와 수정 여부를 반영한다.

## 상태별 액션

| 문서 상태 | Open | Convert | Save / Save As |
| --- | --- | --- | --- |
| `Empty` | 활성 | 비활성 | 비활성 |
| `Ready` | 활성 | 활성 | 비활성 |
| `Converting` | 비활성 | 비활성 | 비활성 |
| `Rendering` | 비활성 | 비활성 | 비활성 |
| `Completed` | 활성 | 활성 | 활성 |
| `Failed` | 활성 | 활성 | 비활성 |

`Rendering`은 선행 구현의 비동기 미리보기 생성 상태다. 초기 미리보기까지 완료되기
전에는 새 파일 열기, 재변환, 저장을 허용하지 않도록 `Converting`과 동일하게
처리한다.

## 구현 경계

이 티켓은 기존 액션 활성화 로직의 중앙화만 수행한다. 문서 전환 전 저장 확인,
검색, 새 액션 또는 후속 티켓의 동작은 추가하지 않는다.

## 확인 항목

1. Qt 6 MSVC 2022 64-bit 구성에서 qmake와 Debug 빌드가 성공하는지 확인한다.
2. 시작 직후 `Open`만 활성화되는지 확인한다.
3. 지원 파일을 열면 자동 변환이 시작되고 `Open`, `Convert`, `Save`, `Save As`가 모두 비활성화되는지 확인한다.
4. 변환 및 초기 미리보기 렌더링 중 네 액션이 모두 비활성화되는지 확인한다.
5. 변환과 렌더링이 완료되면 네 액션이 모두 활성화되는지 확인한다.
6. 변환 실패 뒤 `Open`과 `Convert`만 다시 활성화되는지 확인한다.
