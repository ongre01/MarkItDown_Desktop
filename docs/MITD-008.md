# MITD-008 — 단일 파일 Drag & Drop

## 구현 범위

- `MainWindow`가 Windows Explorer의 로컬 파일 드롭을 받도록 했다.
- 드롭한 파일은 File 메뉴와 툴바의 `Open`이 사용하는 공통 문서 열기 로직으로
  전달한다.
- 지원 확장자는 기존 단일 파일 Open과 동일한 `pdf`, `docx`, `pptx`, `xlsx`,
  `xls`, `html`, `htm`, `csv`, `json`, `xml`, `txt`이다.
- 하나의 지원 파일만 현재 `Document`에 등록하며 상태를 `Ready`로 변경한다.
- 복수 파일, 폴더, 로컬 파일이 아닌 URL, 존재하지 않는 파일, 지원하지 않는
  확장자는 현재 문서를 변경하지 않고 거부한다.

## 드롭 처리

```text
드롭 입력
  │
  ├── URL 아님 / 변환 또는 렌더링 중 ──► 거부
  ├── URL 개수가 1이 아님 ─────────────► 안내 후 거부
  ├── 로컬 파일이 아님 ────────────────► 안내 후 거부
  ├── 폴더 또는 존재하지 않는 파일 ────► 안내 후 거부
  ├── 지원하지 않는 확장자 ────────────► 안내 후 거부
  └── 지원하는 파일 하나 ──────────────► Open 공통 로직으로 Ready 등록
```

복수 파일 드롭 시 티켓에 지정된 다음 메시지를 표시한다.

```text
한 번에 하나의 파일만 열 수 있습니다.
```

편집기와 미리보기 위에서도 창 단위 드롭 처리가 동작하도록 두 위젯의 자체 드롭
처리는 비활성화했다. 드롭한 경로를 Markdown 본문에 삽입하지 않는다.

## 동작 범위

이 기능은 MITD-003과 동일하게 파일 경로를 등록하는 단계까지만 수행한다. 드롭 즉시
MarkItDown 변환을 시작하지 않는다. 수정된 Markdown이 있을 때 저장 여부를 묻는
후속 티켓의 동작도 포함하지 않는다.

## 관련 파일

- 드래그 진입, 드롭 검증, 공통 문서 열기: `mainwindow.h`, `mainwindow.cpp`
- 구현 및 수동 확인 절차: `docs/MITD-008.md`

새 소스 파일이나 Qt 모듈은 추가하지 않는다.

## 확인 항목

1. Qt 6 MSVC 2022 64-bit 구성에서 qmake와 Debug 빌드가 성공하는지 확인한다.
2. Explorer에서 지원하는 파일 하나를 드롭했을 때 창 제목과 상태 표시줄에 파일명이
   나타나고 상태가 `Ready`인지 확인한다.
3. 파일 두 개 이상을 함께 드롭했을 때 지정된 안내 메시지가 나타나고 현재 문서가
   바뀌지 않는지 확인한다.
4. 폴더를 드롭했을 때 안내 메시지가 나타나고 현재 문서가 바뀌지 않는지 확인한다.
5. 지원하지 않는 확장자의 파일을 드롭했을 때 안내 메시지가 나타나고 현재 문서가
   바뀌지 않는지 확인한다.
6. 지원 파일 드롭 후 변환이 자동 시작되지 않고 `Convert`를 직접 실행해야 하는지
   확인한다.
