## 작업 내용

### 1. Qt Test 환경 추가

다음과 같은 테스트 구조를 프로젝트 build system에 통합한다.

```text
tests/
└── unit/
    ├── tst_DocumentFileOperations.cpp
    ├── tst_MarkdownRenderState.cpp
    ├── tst_ConversionErrorPresentation.cpp
    └── tst_MarkdownDocumentRenderer.cpp
```

기존 프로젝트 구조가 다르면 기존 구조를 우선한다.

---

### 2. DocumentFileOperations 테스트

다음을 검증한다.

```text
지원되는 Source Document
존재하지 않는 파일
Directory
지원하지 않는 extension
Markdown 출력 경로
Markdown extension normalization
UTF-8 저장
파일 저장 실패
```

파일 테스트에는 다음을 사용한다.

```cpp
QTemporaryDir
QTemporaryFile
```

developer PC의 절대 경로에 의존하지 않는다.

---

### 3. MarkdownRenderState 테스트

다음을 검증한다.

```text
Request ID 생성
최신 Request accept
이전 Request reject
invalidate
completeRequest
Initial Request 여부
Rendered HTML 저장
Editor insertion 완료 상태
Initial Preview ready 상태
```

특히 다음 race condition을 반드시 검증한다.

```text
Request #1 시작
        │
Request #2 시작
        │
Request #2 완료
        │
Request #1 늦게 완료
```

Expected:

```text
#2 accepted
#1 rejected
```

---

### 4. Initial Preview 상태 조합

실제 구현이 Render 완료와 Editor insertion 완료를 모두 요구한다면 다음 네 가지를 모두 테스트한다.

| Render | Editor | Ready |
| ------ | ------ | ----- |
| No     | No     | No    |
| Yes    | No     | No    |
| No     | Yes    | No    |
| Yes    | Yes    | Yes   |

---

### 5. ConversionErrorPresentation

실제 정의된 모든 `ConversionError`를 Qt Data Driven Test로 검증한다.

예:

```text
AlreadyRunning
ExecutableNotFound
FailedToStart
Crashed
NonZeroExit
EmptyOutput
ProcessFailure
```

실제 enum 정의를 source에서 확인한 후 테스트한다.

---

### 6. MarkdownDocumentRenderer

최소 다음을 테스트한다.

```text
empty
heading
bold
multiline
unicode
```

전체 HTML 문자열 exact match는 가능한 한 피한다.

의미 있는 결과를 검증한다.
