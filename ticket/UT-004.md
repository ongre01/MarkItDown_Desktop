# TICKET-UT-004

# DocumentController Component Test 구현

## Depends On

```text
TICKET-UT-003
```

필요하면 UT-002의 Fake Manager 구조를 재사용한다.

---

## 목표

`DocumentController`가 conversion backend와 UI 사이에서 올바르게 동작하는지 검증한다.

---

## 확인 대상

현재 구조에서 확인되는 관계:

```text
DocumentController::convert()
        │
        └── MarkItDownManager::convert()

DocumentController::isConverting()
        │
        └── MarkItDownManager::isRunning()
```

실제 source에서 signal forwarding 및 error handling도 확인한다.

---

## 테스트 Scenario

### convert delegation

```text
controller.convert(source)
        ↓
manager.convert(source)
```

정확한 source path가 전달되는지 확인한다.

---

### converting state

Manager:

```text
running = false
running = true
```

각각에 대해:

```text
controller.isConverting()
```

결과를 검증한다.

---

### conversion started forwarding

Manager가 conversion started signal을 발생시키는 경우 Controller가 contract에 맞게 전달하는지 확인한다.

---

### conversion success forwarding

Manager success:

```text
Markdown Result
```

Controller가 동일하거나 정의된 형태로 상위 계층에 전달하는지 확인한다.

---

### conversion error forwarding

각 Manager error가 Controller를 통해 예상한 형태로 전달되는지 확인한다.

---

### duplicate state / unexpected result

Controller가 별도의 state validation을 수행하는 경우 실제 구현에 맞춰 negative case를 추가한다.

---

## 원칙

Controller test에서는 실제 QProcess를 사용하지 않는다.

Fake 또는 test double Manager를 사용한다.
