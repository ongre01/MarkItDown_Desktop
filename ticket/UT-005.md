# TICKET-UT-005

# MainWindow UI Behavior Test 구현

## Depends On

```text
TICKET-UT-001
TICKET-UT-003
TICKET-UT-004
```

---

## 목표

private helper 함수가 아니라 사용자에게 보이는 `MainWindow` workflow를 테스트한다.

---

## 테스트 접근

다음 흐름을 중심으로 한다.

```text
Open
  ↓
Convert
  ↓
Markdown Editor
  ↓
Preview
  ↓
Save
```

실제 external process는 사용하지 않는다.

Controller / Manager는 Fake 또는 controlled implementation을 사용한다.

---

## 테스트 Scenario

### 정상 Source Document Open

Expected:

```text
선택된 document 반영
UI state 갱신
Convert 가능한 상태
```

---

### Conversion 시작

Expected:

```text
busy state 적용
중복 conversion 방지
관련 control state 갱신
```

실제 UI contract에 따라 검증한다.

---

### Conversion 완료

Fake controller에서 Markdown 결과 발생.

Expected:

```text
Markdown editor 갱신
Initial Preview rendering 시작
최종 Preview 갱신
UI busy 상태 종료
```

---

### Conversion 실패

Fake controller error 발생.

Expected:

```text
UI state 정상 복구
error presentation 발생
```

Modal dialog 자체를 과도하게 테스트하지 않는다.

가능하면 presentation 또는 observable state를 검증한다.

---

### Markdown Editor 수정

```text
Editor text 변경
        ↓
Preview render request
```

실제 delay/debounce 정책이 있다면 QTRY 계열을 사용한다.

고정 sleep은 사용하지 않는다.

---

### Stale Render Result

가장 중요한 UI-level race test다.

```text
Markdown A 입력
Render A 시작

Markdown B 입력
Render B 시작

Render B 완료
Render A 늦게 완료
```

Expected:

```text
Preview = B
A 결과 무시
```

---

### Save

Markdown 저장을 사용자 workflow 수준에서 확인한다.

filesystem은 temporary location을 사용한다.

---

### New Document / New Conversion

새 작업 시작 시 이전 Render Request가 invalidation 되는지 확인한다.

---

## 테스트하지 않을 것

private helper:

```text
insertNextEditorChunk()
finishEditorInsertion()
updateUiState()
```

등을 단독 호출해서 테스트하지 않는다.

public behavior를 통해 간접적으로 검증한다.

---

## Acceptance Criteria

```text
[ ] Open behavior 테스트
[ ] conversion started UI 상태 테스트

[ ] conversion failure 테스트
[ ] editor → preview update 테스트
[ ] stale render rejection 테스트
[ ] save workflow 테스트
[ ] 새로운 작업 시 이전 async 결과 무효화 검증
[ ] 실제 external process 불필요
[ ] arbitrary sleep 없음
[ ] docs/ 업데이트
```
