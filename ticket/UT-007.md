# TICKET-UT-007

# Test Build / CTest / Verification 통합

## Depends On

```text
TICKET-UT-001 ~ UT-006
```

---

## 목표

구현한 자동 테스트를 개발자가 일관된 명령으로 build 및 실행할 수 있도록 프로젝트 workflow에 통합한다.

---

## 작업 내용

### CTest Integration

프로젝트가 CMake 기반이고 기존 구조와 충돌하지 않는다면 테스트를 CTest에 등록한다.

예:

```cmake
enable_testing()
```

그리고 각 test executable:

```cmake
add_test(
    NAME tst_DocumentFileOperations
    COMMAND tst_DocumentFileOperations
)
```

정확한 구현은 기존 CMake 구조를 따른다.

---

## Test Group

가능하면 테스트를 다음처럼 구분 가능하도록 한다.

```text
unit
component
ui
```

예:

```text
ctest -L unit
ctest -L component
ctest -L ui
```

단, 기존 build convention과 맞는 경우에만 적용한다.

---

## Standard Verification

`BUILD_GUIDE.md`를 기준으로 표준 build/test command를 문서화한다.

예시 형태:

```text
Configure
Build Application
Build Tests
Run Unit Tests
Run Component Tests
Run UI Tests
Run All Tests
```

실제 명령은 프로젝트에서 확인하여 기록한다.

---

## Failure Handling

테스트 실패 시 다음 정보가 충분히 보이도록 한다.

```text
test executable
test case
expected
actual
Qt diagnostic
```

---

## Coverage

Coverage tool이 이미 프로젝트에 존재한다면 연동한다.

없다면 이번 티켓에서 새로운 coverage infrastructure를 강제로 도입하지 않는다.

필요하면 별도 티켓으로 분리한다.

Coverage percentage를 acceptance criterion으로 사용하지 않는다.

---

## Documentation

최종 테스트 문서를 정리한다.

권장:

```text
docs/unit-tests.md
```

또는 기존 테스트 문서가 있다면 해당 문서를 업데이트한다.

포함 내용:

```text
테스트 architecture
테스트 directory
test category
build 방법
실행 방법
각 test suite 목적
Fake / Mock architecture
현재 제외 항목
known limitations
```

---

## Full Verification

최종적으로 다음 순서로 실행한다.

```text
Clean / configured build
        ↓
Application build
        ↓
Unit Tests
        ↓
Component Tests
        ↓
UI Tests
        ↓
All Tests
```

실제 실행하지 않은 명령을 PASS로 기록하지 않는다.

---

## Acceptance Criteria

```text
[ ] 모든 test executable build 가능
[ ] Unit Test 일괄 실행 가능
[ ] Component Test 일괄 실행 가능
[ ] UI Test 실행 가능
[ ] 전체 test suite 실행 가능
[ ] application normal build 성공
[ ] 실행 방법 docs/에 기록
[ ] 실제 test result 기록
[ ] 알려진 실패/제약 사항 명시
```

# 최종 테스트 구조

전체 티켓 완료 후 권장 구조:

```text
tests/
├── unit/
│   ├── tst_DocumentFileOperations.cpp
│   ├── tst_MarkdownRenderState.cpp
│   ├── tst_ConversionErrorPresentation.cpp
│   └── tst_MarkdownDocumentRenderer.cpp
│
├── component/
│   ├── tst_MarkItDownManager.cpp
│   └── tst_DocumentController.cpp
│
├── ui/
│   └── tst_MainWindow.cpp
│
└── CMakeLists.txt
```

production 쪽 testability abstraction이 필요한 경우:

```text
src/
├── process/
│   ├── IProcessRunner.h
│   └── QProcessRunner.*
│
└── markitdown/
    ├── MarkItDownManager.*
    └── MarkItDownExecutableResolver.*
```

실제 디렉터리 구조는 현재 프로젝트 구조를 우선한다.
