# TICKET-UT-002

# MarkItDown Process Testability Refactoring

## 목표

`MarkItDownManager`가 실제 `QProcess` 및 개발환경에 직접 의존하여 테스트하기 어려운 부분을 최소한으로 분리한다.

이 티켓에서는 behavior를 변경하지 않는다.

---

## 배경

현재 Manager가 다음 책임을 동시에 가지고 있다면 테스트가 어려워진다.

```text
Executable 탐색
Process 실행
stdout 수집
stderr 수집
exit 상태 판단
ConversionError 생성
```

Process boundary를 제어 가능하도록 만든다.

---

## 작업 내용

### 1. Process 실행 경계 분석

현재 `MarkItDownManager`에서 다음 사용을 확인한다.

```text
QProcess
start
finished
errorOccurred
stdout
stderr
exitCode
exitStatus
```

실제 implementation을 확인하고 필요한 최소 abstraction만 만든다.

---

### 2. Process Runner abstraction

필요한 경우 다음 구조를 도입한다.

```text
MarkItDownManager
        │
        ▼
IProcessRunner
        ▲
        │
 ┌──────┴──────────┐
 │                 │
QProcessRunner   FakeProcessRunner
Production       Test
```

interface는 실제 Manager가 사용하는 기능만 노출한다.

과도한 generic process framework를 만들지 않는다.

---

### 3. Executable Resolver 분리

현재 다음과 같은 executable discovery 로직이 Manager 내부에 있다면 분리를 검토한다.

```text
resolveMarkItDownExecutable()
findApplicationLocalExecutable()
findDevelopmentEnvironmentExecutable()
existingFilePath()
```

필요한 경우:

```text
IMarkItDownExecutableResolver
            ▲
            │
MarkItDownExecutableResolver
```

형태로 분리한다.

---

### 4. Dependency Injection

production에서는 기존과 동일하게 실제 구현을 사용한다.

test에서는 Fake를 주입할 수 있도록 한다.

---

## 중요한 제약

다음은 금지한다.

```text
private → public
#define private public
test용 production branch
test environment global flag
production behavior 변경
```

---

## Verification

refactoring 전후에 application behavior가 동일한지 확인한다.

기존 Unit Test도 모두 실행한다.
